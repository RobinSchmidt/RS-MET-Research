def linear_interp_pair():
    """Linear interpolation kernel (triangle, gain L) padded to centre L, d = [1]; latency 1."""
    n = np.arange(-(L - 1), L)
    tri = 1.0 - np.abs(n) / L
    return np.concatenate([[0.0], tri]), np.array([1.0])

In spec.py, it lists the conventions used in the library. It says:

* Frequencies are in radians per HIGH-rate sample, ``w`` in ``[0, pi]``.  The original Nyquist
  frequency is therefore ``pi / L``.
* ``passband`` is the passband edge as a FRACTION of the original Nyquist frequency, i.e. the edge is
  at ``passband * pi / L`` (``0 < passband < 1``).  At a base rate of 44.1 kHz, ``passband = 0.9``
  means 19.8 kHz.

That is inconsistent. I think, all frequency-like parameters should be given in the same unit. 
Either all frequencies are given in 0.. pi or all in 0..1. Look up what conventions comparable 
libraries use and maybe mimic that. I think Matlab uses 0..1 or 0..0.5 but the latter would be a bit
weird. OK - it means "fraction of the sample rate" and 0.5 is the highest possible value for that 
but even knowing that, it's still weird. Look up what standard Python DSP libraries use and maybe 
follow that. Or maybe try to figure out the reason for this inconsistent convention. Maybe there's a
good reason for it that I don't see. And/or: Maybe request a code review in a new session or better:
Request multiple reviews from different models. Maybe they will also flag that inconsistency?

Verify this:

When we use the kernels u,d specifically for upsampling and downsampling rather than for filtering
arbitrary signals at the oversampled rate, we unlock an optimization that is known as "polyphase 
filtering" in the DSP literature. It works as follows:

Polyphase upsampling takes advantage of the fact that only every L-th sample of the zero-stuffed 
input signal is nonzero. It avoids computing the zero contributions from the zero samples to the 
FIR convolution sum. 

Polyphase downsampling takes advantage of the fact that in the decimation stage, we will throw away 
all samples except every L-th anyway. It avoids to compute these extra samples that we will not need
anyway.

So, the polyphase upsampling and downsampling stages merge the filter-then-upsample and
filter-then-downsample steps into a single operation.
