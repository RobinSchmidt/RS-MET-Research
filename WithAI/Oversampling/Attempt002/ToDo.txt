    """Linear interpolation kernel (triangle, gain L) padded to centre L, d = [1]; latency 1."""
    n = np.arange(-(L - 1), L)
    tri = 1.0 - np.abs(n) / L

Verify this:

When we use the kernels u,d specifically for upsampling and downsampling rather than for filtering
arbitrary signals at the oversampled rate, we unlock an optimization that is known as "polyphase 
filtering" in the DSP literature. It works as follows:

Polyphase upsampling takes advantage of the fact that only every L-th sample of the zero-stuffed 
input signal is nonzero. It avoids computing the zero contributions from the zero samples to the 
FIR convolution sum. 

Polyphase downsampling takes advantage of the fact that in the decimation stage, we will throw away 
all samples except every L-th anyway. It avoids to compute these extra samples that we will not need
anyway.

So, the polyphase upsampling and downsampling stages merge the filter-then-upsample and
filter-then-downsample steps into a single operation.

- Does the stopband have to be 2-passband? Can we let the user (optionally) set that to something
  else? For example by passing (..., passband=0.9, stopband=1.05, ...). Would the design then also 
  support settings like passband=0.9, stopband=1.0 or even  passband=0.8, stopband=0.9 or

  -> Answered at the start of the 3rd session and the answer is: no, the stopband cannot be 
     meaningfully set independently due to symmetry constraints resulting from the perfect 
     reconstruction requirement. The relevant part of the answer was:
  "Nyquist(L) means the images of H = U·D sum to a constant. If H ≈ 1 up to wp and H ≈ 0 from ws (in
  fractions of the original Nyquist), then H(w) + H(2 - w) = 1 must hold. So the transition band 
  must be antisymmetric about 1, and only min(1 - wp, ws - 1) is meaningful."
